# Edge AI bottleneck atlas (scoped to what this project can speak about)

Evidence labels: **[M]** measured in this project's simulator / RTL transcription (model-level); **[K]** general domain knowledge written from recall, NOT verified against sources; **[-]** not studied. Scope decision: memory scheduling for a small INT8 GEMM accelerator. Items marked out of scope are listed so the gap is explicit, not because they are unimportant.

## Fundamental versus workload-dependent versus architectural [K, with evidence where measured]
* **Fundamental:** compulsory traffic (each input read, each output written once); arithmetic intensity of the operator; on-chip capacity bounds reuse.
* **Workload-dependent:** whether a workload is memory- or compute-bound (5 vs 25 of 30 here); shape sensitivity of the best schedule (prefill yes, KV-decode no).
* **Architecture/implementation-induced:** bank conflicts (up to ~8x here, removable), fixed tile shapes (13-19 % cycles), single buffering (loses overlap), descriptor size (program memory exceeds data memory for D on average).

## Out of scope for this project (explicitly)
Near/in-memory computing, sparsity engines, learned scheduling policies, multi-model execution, online learning, reliability and security of shared memory, thermal modelling.
